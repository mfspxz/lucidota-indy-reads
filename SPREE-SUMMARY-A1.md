## 2. Fixes & changes

### 2a. rt6_gmail_intake hermetic fixture (test-only)
Embedded the missing `hatch_gws_cli` fixture as a bash script generated by the
test itself (`std::sync::Once` → `/tmp/rt6/bin`, PATH prepended). Fixture
handlers: `gmail status` → connected; `gmail +triage --query` (query

### 2b. REAL AUTH GAP CLOSED — Rust axum server had zero auth (`src/api.rs`)
All 5 JS (Vercel) handlers were fail-closed (`api/_auth.js`, verified). The
native Rust server bound `0.0.0.0` with **no auth at all** — anyone could hit
`/api/turn` (burns router quota), `/api/mcp/*` (executes tools), `/ws`.

Added `require_api_key` middleware:
- Constant-time key comparison (no timing oracle).
- Carriers: `x-api-key` header, `Authorization: Bearer`, `?key=` query.
- Key source: `~/workspace/keys/ROUTER_KEY` (file first), then `ROUTER_KEY` env.
- **Fail-closed 500 if unconfigured** (never fail-open).
- Applied to all `/api/*` routes + `/ws`. `/health` stays open (standard
  liveness probe, returns no sensitive data — deviation from JS noted below).
  Static `web/` stays open (UI shell).

### 2c. Real bug: `percent_decode` emitted `\0` on trailing `%` (`src/api.rs`)
A trailing bare `%` produced a null byte. Now emits the `%` literally.
Added unit tests: `percent_decode` edge cases + constant-time eq.
Bin tests: 23 → 25.

### 2d. Real false-positive: `governor.rs::validate_reply` flagged honest negations
`"not proven"` / `"never been proven"` / `"isn't proven"` / `"Definitely not
proven."` were flagged as claiming PROVEN under an UNKNOWN verdict — the
collapsed substring "notproven" contains "proven", and only "unproven" was
excluded. The guard was punishing the most honest sentences in the system.

Fix: `negated_proven` / `negated_disproven` guards checked **before** positive
patterns, with expanded collapsed-form coverage (`notbeenproven`,
`neverbeenproven`, `hasntbeenproven`, `wasntproven`, `cantprove`, `notrefuted`,
etc.). Also fixed `"definitely not X"` over-matching: `"Definitely not
proven."` was read as a debunking via `has("definitelynot")` — now
`definitelynotproven` is excluded (it's a hedge, not a debunk).
Added 4 cases to `test_validate_reply_honest_negations_pass`.

### 2e. Test harness auth (`tests/equiv_turn_paths.rs`)
The new middleware broke 2 integration tests (expected — they called the API
without auth). Updated the harness to read `~/workspace/keys/ROUTER_KEY` and
send it as `x-api-key` on all `/api/turn` and `/api/receipts` calls, including
the concurrency probe. `/health` polling left unauthenticated (open by design).
